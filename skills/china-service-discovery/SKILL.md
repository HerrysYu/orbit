# 国内任务：先查方法，再拆解派单

你是管家模型。本 skill 负责发现「这件事现在怎样办、用什么服务和渠道能办成」，执行细节交给 worker。**接到新的国内服务任务，先做实时方法检索，再确定执行平台与任务步骤。不得仅凭记忆、平台名单或过去的成功路径直接派单。**

## 1. 理清要办什么

提取目标、城市 / 管辖地、时间、预算、用户已有订单或账号、授权范围和完成标准。把「查信息」「比较方案」「预约 / 下单」「付款」「修改已有订单」区分清楚；它们可能需要不同的入口。先查记忆和当前上下文，确实影响路线且无法合理默认的信息才问用户。

纯写作、编程和本地文件整理无需套用本技能。已有任务的继续执行可复用本任务内仍有效的检索结果；入口失效、地区变化、政策 / 价格变化或换了目标时重新核验。

## 2. 实时检索办理方法

使用大脑当前具备的网页搜索，寻找该任务的官方说明和现行入口。例如：

- `<城市或地区> <具体事项> 官方 办理 入口`
- `<服务商或机构> <查询/预约/退改/开票等动作> 官网 App 小程序`
- `<目标服务> 网页端 能否办理 <关键步骤>`

根据任务选择查询词，不机械执行所有模板。检索官方业务页面、帮助中心、地区办事指南；打开或读取支持判断的具体页面，不能只凭搜索摘要判定流程可用。社区经验可提供线索，再回到实际服务核验。注意发布时间和适用地区，不把广告、旧教程或仿冒入口当官方。

不熟悉领域时，从下方「国内服务检索地图」寻找检索起点。其中 App 和网站均为候选种子，**不是路由白名单、穷尽名单或推荐排名，不能代替本次检索**。更适合的新服务、地方平台、商家自有入口都可以采用。

先确认目标步骤能否完成：网站能介绍业务，不代表能提交申请；能查价格，不代表能买；同一服务的查询、下单和售后可能在不同渠道。搜索没有结果或检索器无法抓取，不等于服务不存在；先检查相关服务接口，再考虑可行的公开网页，不要直接跳到截图点击。

查找办理方法时使用通用事项，不把身份证、手机号、完整订单号、验证码等输入搜索引擎。必要的个人参数只交给完成操作所需的已授权渠道。

## 3. 核对当前执行能力

按相关性查看资源，不为无关平台枚举所有工具。每项外部服务任务在确定执行渠道前，先用 `mcp_list` 和/或 `connectors_list` 查目标步骤相关的当前能力：优先使用已暴露、权限覆盖且能完成具体步骤的服务专用 MCP / 插件。已列出的 connector 单步用 `connector_call`；多步或内置目录 MCP 派给 worker，并在任务单点名插件 / MCP，内置项通过 `codex_session_create(mcp_services=[...])` 按 ID 选择。`configured` 只表示本机配置齐备，不代表连接成功、账号鉴权或业务权限；由实际连接和调用确认。
- 缺少服务接口、配置或账号权限时停止重复尝试，告诉主人需要连接或授权什么；不要自动安装、修改 MCP 配置或索取凭据。若用户没有指定渠道且官方公开网页能完成目标步骤，再用搜索、可行的浏览器或按需且已确认可用的浏览器 MCP（例如 Playwright）；服务专用结构接口已覆盖时不要改用通用浏览器。
- 只有服务接口和网页路径都不能覆盖、且目标步骤确实需要 UI 时才派 `computer_use_task`；只有手机 App / 手机登录态不可替代时才派 `phone_task`，使用服务自己的独立 App。派发时写出当次选择 UI 的实际原因。`phone_status` 只检查手机工具配置；**配置可用不等于设备在线、App 已安装或账号已登录**，未确认条件写给 worker 检查。
- 微信小程序、公众号、微信服务目前没有自动通道：专用手机用不了微信，Mac 微信会拦截 computer use。先找该服务的独立 App 或网页；都没有，就告诉主人这件事需要他在自己手机的微信里完成，并给出具体步骤（搜什么名字、点哪里），不派给手机，也不用 Mac 的 computer use。除此类已知技术限制外，不把某个品类永远绑定到某个 App 或设备。
- 查到只能本人、电话或线下办理的步骤，安排主人完成相应部分；不可假称自动化能代办。需要联系他人时遵循已有发送授权规则。

## 4. 选择方法，再拆任务

以完成用户目标为依据，考虑：接口 / 入口是否官方或可验证、是否覆盖目标地区和完整步骤、当前权限、时效与总费用、实际工具能力，以及是否需要人工验证。存在已授权且覆盖该步骤的服务 MCP / 插件时优先用它；否则先选可行的公开网页，UI 是最后的界面路径。用户指定渠道时遵循指定；发现其无法完成时说明原因再提供可行替代，不静默换成另一种收费业务。

简单任务确认一个官方可行入口即可；存在费用、服务范围或结果差异时，再比较相关候选。不要为了凑平台数量扩大任务，也不要因为某个 App 熟悉就跳过方法检索。

在任务背景和 worker 任务单里留下简短的「方法依据」：

```text
目标与完成标准：…
本次检索：来源页面链接 / 查询时间 / 适用地区
选择的方法：服务名称 + 实际入口 + 网页/connector/手机/人工
选择理由：这个入口支持哪些具体步骤
已确认与待核实：设备、登录、权限、库存/名额等
备用方法与切换条件：…（存在合理备选时）
授权与停止条件：只查询 / 明确授权的购买范围 / 需要人工的步骤
```

这些是任务背景，不是新增工具参数；使用现有 `task_create`、`task_update` 和派单接口。拆解后的步骤写具体动作和验收标准，不使用「在某 App 里随便看看」这样的开放任务。多渠道的研究可以并行；同一手机或 Mac GUI 按现有占用规则串行。

手机派单再按 `china-services` 和 `phone-automation` 执行。方法发现不扩大授权：仅查询仍不下单 / 付款；用户已经明确授权的手机购买按既有策略执行并审计。登录、验证码、扫码、人脸识别等由 worker 结束并交回 `needs_human`，管家通过 `notify` 和 `ask_user` 告知主人。

## 5. 执行后重新判断

worker 回报入口不可用、必须 App、无本地服务或账号受限时，更新方法判断，再选择已核验的备选。不要在同一路径反复开 session，也不要凭旧教程换坐标硬点。服务发生变化时把新的、带日期的结论写进当前任务背景；用户偏好才按现有记忆规则保存，不把一次失败固化成永久平台禁用。

验收实际结果、截图或业务确认信息后再完成任务。对用户只说必要结论，例如「我查了官方办理渠道，这项需要在当地政务平台预约；材料清单已确认，实名验证需要你来完成」，不倾倒内部工具流程。无法查证的入口、费用或能力明确标为未确认。

## 国内服务检索地图

编写于 2026-10-15。以下是寻找方法时的领域提示和候选入口，**不是固定平台分配表**。产品名称、覆盖城市、业务入口和网页能力会变化；每个新任务按 SKILL.md 重新检索适用方法。链接用于发现官方信息，不保证本机可抓取、已登录或能自动操作；不能用这里的名单代替实际能力检查。

### 吃喝、门店与即时服务

- 找餐厅、排队、团购、外卖、咖啡点单：可从美团、大众点评、当前可用的外卖 / 即时零售平台、品牌自有 App 或小程序开始比较。大众点评的[公开入口](https://m.dianping.com/)可作为检索起点；具体商品、配送与下单能力仍需当次核验。
- 先查城市、门店、营业 / 配送范围，再选平台。品牌自有入口可能更直接；聚合平台可能便于比较，不能据此假定哪家最便宜。

### 城市交通与路线

- 路线、距离、公交、停车和附近地点：可检索[高德地图](https://www.amap.com/)、百度地图及当地交通官方入口。
- 打车、出租车、公交乘车码、共享骑行：查服务商当前支持的城市和入口；路线查询网页可用，不代表能在网页叫车。区分路线估算、实时车价与实际叫车订单。

### 火车、航班与长途出行

- 铁路可从[铁路12306](https://www.12306.cn/index/)的现行业务说明核验查询、候补、退改和购票入口。
- 航班和酒店可比较航司 / 酒店自有渠道与[携程](https://www.ctrip.com/)、其他当期可用服务。修改或退款先查订单出票 / 预订渠道，不凭查价入口推断售后入口。
- 检索这次行程适用的规则与总费用，不把旧页面上的时限、服务费或库存写死。

### 旅游、文化与活动

- 景区、博物馆、展览：先找场馆官网、认证公众号和当期预约公告，再核对是否授权第三方售票。
- 演出、电影和体育赛事：可检索主办方、场馆、猫眼、大麦等候选，核对指定售票渠道、城市、场次与退改条件。不要因为某平台知名就认定它有目标场次。

### 网购、比价、售后与二手

- 京东、淘宝 / 天猫、品牌官网 / App、拼多多及其他匹配服务可作为候选；二手任务还可检索闲鱼、转转或品类专门平台。
- 查具体商品规格、卖家身份、到手总价、交付和售后。价格发现、实际购买、发票和退换货未必在同一入口；已有订单优先核验原购买平台的流程。

### 快递、寄件与物流

- 根据承运商检索[顺丰](https://www.sf-express.com/)、邮政 / EMS、京东物流等官方查询或寄件入口；菜鸟及电商订单页也可作为候选。
- 运单查询、寄件预约、地址修改、拦截和理赔是不同能力，分别核验。没有真实状态时不能把通用时效当作用户包裹的配送承诺。

### 医疗、挂号与医保

- 挂号、报告、缴费先查医院官网 / 认证公众号、当地卫生健康部门和官方预约平台；核对院区、科室、日期、放号与身份验证条件。不能把广告转诊页当医院官方入口。
- 医保事项可从[国家医疗保障局](https://www.nhsa.gov.cn/)和[国家医保服务平台](https://fuwu.nhsa.gov.cn/)查现行指南，再定位到实际参保地。医疗服务办理渠道不等于医学诊断依据。

### 政务、证照与地方办事

- 从[国家政务服务平台使用指南](https://gjzwfw.www.gov.cn/col/col1599/index.html)、目标地区政府和主管部门的办事指南查起。随申办、粤省事、浙里办等是地方入口的例子，不能跨地区照搬。
- 居住证、户籍、出入境、车辆、婚育、不动产等，先确认事项管辖地和申请人条件，再核验官网、App、小程序或窗口中哪种能完成目标步骤。

### 社保、公积金、税务与教育

- 社保可从[全国人社政务服务平台](https://www.12333.gov.cn/)、电子社保卡及参保地人社部门查起；公积金看缴存地公积金中心与当地政务指南。
- 个税可检索[自然人电子税务局](https://etax.chinatax.gov.cn/)和「个人所得税」App 的官方说明；其他涉税业务按纳税主体、地区和事项找对应税务入口，不把个人端用于企业事项。
- 学籍、学历等可从[学信网查询说明](https://www.chsi.com.cn/xlcx/index.jsp)查起；考试、录取和学校事务以主管机构或学校当前官方通知为准。

### 通信、水电燃气与家庭服务

- 话费、账单、宽带和业务变更可从实际运营商的官方入口查起，例如[中国移动](https://www.10086.cn/)、中国联通、中国电信；按号码归属、套餐和地区核验。
- 电费、水费、燃气、供暖、物业维修查服务地址对应的公用事业单位 / 物业入口。网上国网、南网在线、支付宝生活缴费、微信生活缴费等只是候选，不代表目标地区和户号一定支持。
- 家政、维修、回收等需要核验本地覆盖、服务商主体和价格构成，不把检索到的联系电话自动当成已获授权的联系对象。

### 银行、企业、招聘与内容信息

- 银行、保险和支付相关操作先找用户实际机构的官方渠道；查询、转账、申领、理赔、销户的条件分别核验。查到某种入口不代表已获授权执行资金操作。
- 企业登记、公示和资质查主管部门与官方登记公示系统；招聘、租房查机构 / 房源方和适配平台的当前入口，核验真实性、地区与用户条件。
- 攻略、评价和内容发现可检索小红书、B 站、知乎、微博、豆瓣等；经验线索与官方事实分开，办事、价格和交易规则最终回到实际服务确认。

### 不在地图里的任务

从「谁负责这件事、官方怎样说明、当前有什么可行渠道」重新搜索。可以使用名单之外的平台、商家直连或人工步骤；不能为了套用已有 App，把用户需求改写成该 App 恰好支持的事情。
